# 微信升级后：重新定位补丁点

补丁点（`0x60df783`）是版本相关的。微信一升级，地址/字节都会变，`wxantirevoke-check`
会报 `[失效]` —— 此时库会**自动跳过、不做任何修改**（写入前逐字节校验），所以不会改坏程序。

重新定位的大致步骤：

## 0. 先确认现状

```bash
wxantirevoke-check                     # 看是哪个补丁点失效了
sha256sum /opt/wechat/wechat           # 记下新版本的哈希，方便以后对照
```

## 1. 找解析 `newmsgid` 的那个函数

```bash
# 关键字符串的虚拟地址（.rodata 的 vaddr == 文件偏移）
strings -a -t x /opt/wechat/wechat | grep -iE 'revokemsg|revoketime|newmsgid|revoke_climsgid'

# 找引用这些字符串的代码（RIP 相对 LEA），然后反汇编
objdump -d -M intel --start-address=<start> --stop-address=<end> /opt/wechat/wechat
```

参考锚点（4.1.13.26）：

| 字符串 | 参考 VA |
|---|---|
| `revokemsg` | `0xf7d9cc` |
| `revoketime` | `0xe61872` |
| `newmsgid` | `0xe023ac` |
| `sysmsg` / `type` / `content` | `0xf34542` / `0xfdab11` / `0xeaa521` |

解析函数（4.1.13.26 是 `0x60df1e0`）的特征：

- 同时引用 `sysmsg` / `type` / `revokemsg` / `content` / `subtype` / `revoketime` /
  `newmsgid` / `revoke_climsgid` / `revokehistoryinjoinroommsg`
- 参数形状是 `(out 结构体, content std::string*, 标志指针)`
- **没有任何直接 `call` 引用它**（由 `0x60df020` 包装函数经 vtable 派发调用）

## 2. 在它内部找 `newmsgid` 的解析片段

```asm
lea  rsi, "newmsgid"
call <get_member>          ; 取成员
call <has_value>           ; 有没有值
mov  rdi, [...]
call <node_to_uint64>      ; ★ 要改的就是这条：改成 xor eax,eax; nop×3
mov  [rbx+0x1c8], rax      ; 存进消息对象
```

判据：紧随其后有一条把返回值写进消息对象某个 8 字节字段的 `mov`，
而且那个字段偏移在后续"按 newmsgid 查原消息"的地方会被读出来
（4.1.13.26 是 `+0x1c8`，在 `0x6adc230` 里被 `mov rax,[r13+0x1c8]` 读取）。

## 3. 改补丁点表

编辑 `wxantirevoke.c` 里的 `pts_4_1_13_26[]`（或新加一个 build 条目）：

```c
{ "newmsgid(<新VA>) -> force 0",
  <新VA>,
  "<原始 5 字节 hex>",
  "31 C0 90 90 90" },          /* xor eax,eax; nop*3 */
```

同时更新：

- `launcher/wxantirevoke-check` 里的 `TABLE`（文件偏移 = VA − 0x1000，以及原始字节）
- `docs/` 里的地址记录

然后 `./install.sh` 重新编译安装。

## 4. 验证

```bash
wxantirevoke-check                          # 应显示 [可用]
WXANTIREVOKE_VERBOSE=1 wechat-antirevoke    # 日志里应出现 写入前/写入后 一对
# 然后让别人真撤回一条消息，确认原文还在
```

## 5. 如果改不动了（结构大改）

用探针重新走一遍定位流程：

```bash
wechat-probe
# 等 15 秒 → wxantirevoke-mark → 让对方撤回 → wxantirevoke-mark
```

`~/.local/state/wxantirevoke/probe.log` 里两个 MARK 之间命中的函数就是这次撤回的真实路径。
若出现新函数，把它加进 `probe/wxprobe.c` 的探针表再测一轮。
详细说明见 [探针-wxprobe.md](探针-wxprobe.md)。

## 附：找函数边界的办法

`.eh_frame_hdr` 里有 FDE 表，可以拿到所有函数起始地址（`datarel|sdata4` 编码的
`(initial_location, fde_ptr)` 对）。解析思路：

```python
# 1. 从 ELF section headers 找到 .eh_frame_hdr（addr/off/size）
# 2. 跳过 4 字节头（version + 3 个编码字节）
# 3. 从 off+12 起每 8 字节一组：loc = base + int32, fde = base + int32
#    把这些 loc 排序，就成了"函数起始地址表"
# 4. 给定任意 VA，用二分找到它所属的函数区间
```

4.1.13.26 有 359,528 个函数起始。用它可以干净地反汇编"某个地址所在的整个函数"，
不用猜函数结束位置。
